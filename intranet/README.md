# ACLiSS 院内サーバー版

院内のWebサーバーにファイルを置くだけで動く版です。インターネット上のサービス
（Vercel・Supabase）を使わず、マスタは院内サーバー上のCSVとPNGで管理します。

## Vercel版との違い

| 機能 | Vercel版 | 院内サーバー版 |
|---|---|---|
| バーコードスキャン・手入力 | ○ | ○（カメラはHTTPSで開いた場合のみ） |
| 容器一覧・容器詳細・検査項目検索 | ○ | ○ |
| 最低採血量の計算 | ○ | なし |
| マスタの更新 | 管理画面から | CSV・PNGファイルを上書き |
| マスタCSVの列名 | 英語（container_code など） | ひな型 ACLiSSマスタ.xlsx と同じ日本語 |
| アクセスログ | 管理画面で確認 | Webサーバー自体のアクセスログで確認 |
| メンテナンス切替・合言葉 | ○ | なし（管理画面そのものがありません） |
| 外部への通信 | Vercel・Supabase | なし |

## 院内サーバーに置くフォルダ

`npm run build:intranet` を実行すると `intranet-dist/` ができます。この中身を丸ごと、
院内のWebサーバーの好きな場所にコピーしてください（例: `https://院内サーバー/acliss/`）。

```
acliss/                  ← フォルダ名・置き場所は自由
├── index.html           ← アプリ本体（以下も含めて上書きで更新）
├── app.js
├── app.css
├── manifest.webmanifest
├── icons/
├── vendor/              ← バーコード読み取り部品（iPhoneなどで使用）
├── master/              ← マスタCSV（院内で管理）
│   ├── containers.csv
│   └── test_items.csv
└── images/              ← 容器写真（院内で管理）
    ├── 073.png
    └── …
```

## Webサーバーの条件

- 静的なファイルを配信できるWebサーバーなら何でも動きます（IIS・Apache・nginx など）。
  サーバー側にプログラムやデータベースは不要です。
- **HTTPS（`https://`）での配信を推奨します。** iPhone・Androidのブラウザは、HTTPSで開いた
  ページでしかカメラを使わせません。`http://` で開いた場合、バーコードは読めませんが、
  ラベルの数字の手入力と、それ以外の機能はすべて使えます。
- IISでは、未登録の拡張子のファイルを配信しない設定になっていることがあります。
  `master/containers.csv` や `manifest.webmanifest` が開けない場合は、MIMEの種類に
  `.csv`（`text/csv`）と `.webmanifest`（`application/manifest+json`）を追加してください。

## マスタの更新方法

### CSV（`master/` フォルダ）

マスタは、ひな型 `ACLiSSマスタ.xlsx` の2つのシートを、それぞれCSVで保存して置きます。

| 置くファイル | 元のシート | 必ず要る列 |
|---|---|---|
| `containers.csv` | 材料 | 材料コード |
| `test_items.csv` | オーダ可能項目 | 項目コード・名称・材料コード |

- Excelで各シートを開き、「名前を付けて保存」で「CSV UTF-8」または「CSV（コンマ区切り）」を
  選んで保存します。ExcelのCSV保存は開いているシート1枚だけなので、シートごとに保存してください。
  次にACLiSSを開いた時から、新しい内容が表示されます。
- 列名（1行目）はひな型と同じにします。列の並び順が変わっても読めます。
- 材料シートの各列の使われ方:

  | 列 | 画面での表示 |
  |---|---|
  | 材料コード | 容器コード（バーコード・ラベル数字の末尾3桁と一致）。`73` のように先頭の0が消えていても `073` として読みます |
  | VESSEL・MATERIAL | 容器名（「VESSEL － MATERIAL」） |
  | 容器払い出し・内線番号① | 払い出し場所。空欄・`#N/A` は「未設定」、内線の `-` は内線なし |
  | 問い合わせ先・内線番号② | 検査問い合わせ先 |
  | 規定採取量 | 採取量。空欄・`----` は「規定なし」 |
  | 指示①〜③ | 指示ラベル。どれかに文が入っている時だけ表示 |
  | 注意事項 | 注意事項 |
  | 画像コード | 表示する写真（下の「写真」を参照） |

- オーダ可能項目シートの「材料コード」が、検査項目から探した時に開く容器です。
- 列名が違うなど読み込めないCSVを置いた場合、端末に前回の内容が残っていればそれを表示し、
  「前回のデータを表示中」と出ます。

### 写真（`images/` フォルダ）

- 写真はPNGで、ファイル名を「容器コード.png」にします（例: `073.png`）。
- 表示されるのは、`containers.csv` の「画像コード」列に書かれた容器コードの写真です。
  同じ写真を使い回している容器は、写真ファイル1つで済みます。
- 写真がない容器は「画像コード」を空欄にします。写真ファイルが見つからない場合も、
  写真の欄が出ないだけで、その他の情報は通常どおり表示されます。

## アプリ本体の更新

新しい `intranet-dist/` の中身で上書きします。このとき、院内で管理している `master/` と
`images/` は上書き・削除しないでください（ビルド結果の `master/`・`images/` には説明の
テキストファイルしか入っていません）。

## 作り直し方（開発者向け）

```bash
npm install
npm run build:intranet              # intranet-dist/ を作る
npm run build:intranet -- --preview # あわせて開発確認用の1ファイル版 intranet-preview/ も作る
```

アプリ本体は、手書きの3ファイルだけでできています。React・Tailwind・TypeScriptなどは使わず、
変換（バンドル）もしていません。Vercel版の画面部品とは共有していないため、院内サーバー版だけを
変更しても、Vercel版には影響しません。

| ファイル | 内容 |
|---|---|
| `intranet/index.html` | ヘッダーと、画面を入れる枠 |
| `intranet/app.css` | 見た目（Vercel版と同じ配色・文字の大きさ・余白） |
| `intranet/app.js` | CSVの読み込み・各画面・バーコードスキャン・画面の切り替え |

`npm run build:intranet` は、この3ファイルにアイコンと、`node_modules` にあるバーコード読み取り
部品（ZXing、`vendor/zxing-browser.min.js`）を添えて `intranet-dist/` に並べるだけです
（`intranet/build.mjs`）。読み取り部品は、ブラウザ内蔵の読み取り（BarcodeDetector）が使えない
端末でだけ読み込みます。画面の切り替えはURLの `#` 以降で行うため、Webサーバー側にURL書き換えの
設定は要りません。

## 端末に残るもの

電波が弱い場所でも使えるよう、読み込んだマスタの控えを端末のブラウザ内に保存します
（Vercel版と同じく、個人情報は含みません）。

# ACLiSS 構成・セキュリティ説明メモ（フェーズ0時点）

情報セキュリティ部門への説明資料のベースとして、フェーズが進むごとにこのファイルを更新していきます。
フェーズ0時点ではプロジェクト雛形のみのため、以下は「今後の設計方針」の確認です。

## ① システム構成図

**当面（私物スマホ運用・外部クラウド構成）**

```
[私物スマホ / iPad ブラウザ]
        │  HTTPS（インターネット経由）
        ▼
[Next.js フロントエンド（ホスティング先は今後選定）]
        │  HTTPS
        ▼
[Supabase（外部クラウド・無料枠）]
   ├─ データベース（容器マスタ・検査項目マスタ）
   └─ ストレージ（容器写真）
```

**将来（病院スマホ運用・院内イントラ構成／スコープ外・参考）**

```
[病院スマホ]
        │  院内ネットワーク内
        ▼
[院内イントラ内サーバー（DB + 画像）]
```

→ フロント側は `src/lib/config.ts` の環境変数（接続先URL）を差し替えるだけで
　将来この構成に移行できるようにしておく。

## ② 通信経路と保存データ一覧

- 通信は「私物スマホ ⇔ 外部サーバー（Supabase等）」の一方向のみ。
  電子カルテなど院内の他システムとは一切連携しない。
- 保存するデータは容器・検査項目のマスタ情報のみ（患者個人情報・要配慮個人情報は保持しない）。
- 通信はHTTPSで暗号化する（ホスティング先の標準対応を利用）。

## ③ 認証・アクセス制御の仕組み（フェーズ2以降で実装予定）

- 閲覧側（看護師利用画面）: 簡易パスコード or Basic認証を予定
- 管理画面（マスタ更新）: ログイン認証を予定
- 検索エンジンにインデックスされないよう `robots.txt` 等で対応予定

## ④ なぜ当面は外部クラウドを使うのか

私物スマホからは院内イントラ内のサーバーへ直接アクセスできないため
（院内Wi-Fi接続時を除く）。マスタに要配慮個人情報を含めないことを前提に、
当面はSupabase（外部クラウドの無料枠）を利用し、将来病院スマホ運用へ移行する際に
院内イントラへ移設する。

## 現時点（フェーズ0）で担保されていること／いないこと

- ○ 担保: まだ外部サーバーへの接続自体を行っていない（雛形のみ・データなし）
- △ 未着手: 認証・アクセス制御、Supabase接続、マスタ投入はフェーズ1・2で実装
